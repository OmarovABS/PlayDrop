# D'VORA

Telegram Mini App — витрина цифровых услуг: первая страница с карточками категорий,
за ней витрина PS5 с каталогом игр, аккаунтами и подписками. Корзина и профиль
общие для обеих страниц.

Статика: три HTML, один CSS, ноль зависимостей, ноль сборки.

## Запуск

Нужен любой статический сервер:

```bash
python -m http.server 8080
```

или

```bash
npx serve .
```

Открыть <http://localhost:8080>. Через `file://` не заработает — mini app требует
корректный origin.

```
.

├── playstation.html        витрина PS5: игры, аккаунты, подписки
├── ai.html                 страница ИИ-подписок
├── styles/
│   └── site.css            единый набор стилей для всех страниц
├── scripts/
│   ├── app.js              общая UI-логика (анимации, фильтры, навигация)
│   ├── user.js             профиль по Telegram ID
│   ├── cart.js             корзина и добавление товаров
│   ├── cart-drawer.js      корзина в виде drawer
│   ├── profile.js          шторка профиля
│   └── telegram.js         Telegram Mini App и уведомления
├── assets/
│   └── images/             изображения игр, иконки и обложки
├── .gitignore
├── README.md
└── .git/
```

В проекте оставлены только те модули, которые реально подключены и участвуют в работе интерфейса:
- `app.js` — общая UI-логика и навигация
- `user.js` — локальный профиль Telegram
- `cart.js` — состояние корзины и расчёт итогов
- `cart-drawer.js` — открытие/закрытие корзины и оформление заказа
- `profile.js` — панель профиля
- `telegram.js` — Telegram bridge и всплывающие уведомления

Лишние legacy-скрипты, которые не используются в HTML и дублируют поведение, удалены.

## Экраны

В проекте три рабочие страницы:

| Файл | Экран |
|------|-------|
| `index.html` | главная витрина услуг |
| `playstation.html` | каталог игр, аккаунтов и подписок PS5 |
| `ai.html` | раздел с ИИ-подписками |

`index.html` открывается как стартовый экран mini app. `playstation.html` умеет переключать секции через хеш, а остальные категории сервисов пока показывают демо-состояние.

`app.js` перехватывает клики по хеш-ссылкам и управляет навигацией внутри вкладок, без лишних роутеров и дублей логики.

## Как это устроено

- **Состояние** живёт в переменных `cart` и `wishlist` и никуда не пишется — ни
  `localStorage`, ни `sessionStorage`, ни запросов. После перезагрузки всё
  возвращается к демо-данным. Это демонстрационный витринный сценарий, а не
  рабочий магазин.
- **Каталог** отрисован прямо в HTML (9 карточек плюс 4 в блоке хитов), фильтр по
  жанру — «все / RPG / Экшен / Спорт и гонки» — переключает `data-catlight` без
  перезагрузки.
- **Обложки игр** — инлайновые SVG-заглушки в base64. Заменяются на реальные
  картинки в атрибуте `src` у `<img>`; ключи лежат в объекте `COVERS` в
  `index.html`.
- **Спрайт иконок** инлайнится в начало `<body>` и подключается через `<use>`.
  Внешний `icons.svg#id` не работает в Chrome, а `fetch` ломается на `file://`.
  Новые иконки добавляются символом в этот же инлайновый спрайт — отдельного
  `icons.svg` в проекте нет.
- **Стили** лежат в `styles/site.css`: дизайн-токены в `:root`, тёмная тема — в
  `@media (prefers-color-scheme: dark)`. В HTML нет ни одного `<style>` и
  `style=` кроме инлайновых точечных настроек.

## Telegram

- Подключается `telegram-web-app.js` и инициализируется в `telegram.js`.
- Применяется тема Telegram, добавляются классы `.tg` и корректируются цвета.
- При кликах по кнопкам добавления товаров и оформления заказа используется haptic feedback Telegram.
- **Отправка заказа** идёт в одном месте: через `cart-drawer.js` в `tg.sendData(JSON)`. Логика не дублируется.
